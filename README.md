# ระบบจำลอง: ยืม-คืนอุปกรณ์ + คำนวณค่าปรับ + แจ้งเตือนผ่าน LINE

โปรเจกต์ต้นแบบ (Prototype) สำหรับทดสอบแนวคิดโมดูลเสริมของระบบยืม-คืนอุปกรณ์
คณะวิทยาการสื่อสาร โดยไม่ต้องเชื่อมต่อฐานข้อมูลจริงของคณะ

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `db_setup.py` | สร้างฐานข้อมูลจำลอง (SQLite) พร้อมข้อมูลทดสอบ: ผู้ใช้, อุปกรณ์, รายการยืม-คืน |
| `fine_calculator.py` | โมดูลคำนวณค่าปรับ: เช็กว่าเลยกำหนดคืนหรือไม่ แล้วคำนวณ (จำนวนวันเกิน × อัตรา/วัน) |
| `line_notify.py` | โมดูลแจ้งเตือนผ่าน LINE พร้อมโหมด dry-run (จำลองการส่ง) และโหมดใช้งานจริง |
| `simulation.py` | สคริปต์รวมทุกโมดูลเข้าด้วยกัน จำลอง flow ทั้งระบบตั้งแต่ต้นจนจบ |
| `library_mock.db` | ไฟล์ฐานข้อมูล SQLite ที่ถูกสร้างขึ้นหลังรัน (ลบแล้วสร้างใหม่ได้ทุกครั้ง) |

## วิธีรัน

```bash
# ไม่ต้องติดตั้งอะไรเพิ่มสำหรับโหมดจำลอง (SQLite และ dry-run LINE ใช้ built-in library ทั้งหมด)
python simulation.py
```

ผลลัพธ์จะแสดง 5 ขั้นตอนตามลำดับ:
1. สร้างฐานข้อมูลจำลอง
2-3. ตรวจสอบวันคืน + คำนวณค่าปรับ
4. ส่งข้อความแจ้งเตือน LINE (โหมด dry-run พิมพ์ข้อความออกหน้าจอแทนการยิง API จริง)
5. สรุปผลและตรวจสอบว่าข้อมูลถูกบันทึกกลับเข้าฐานข้อมูลถูกต้อง

## อัตราค่าปรับ

ค่าเริ่มต้นคือ **100 บาท/วัน** (ปรับได้ที่ `DEFAULT_FINE_RATE_PER_DAY` ใน `fine_calculator.py`
หรือส่งค่า `rate_per_day` เข้าไปตอนเรียกใช้ฟังก์ชัน)

## การเชื่อมต่อ LINE จริง (เมื่อพร้อมใช้งานจริง)

1. สร้าง Messaging API channel ที่ [LINE Developers Console](https://developers.line.biz/console/)
2. คัดลอก **Channel access token (long-lived)**
3. เก็บค่า `line_user_id` ของผู้ใช้แต่ละคน (ได้จาก webhook หรือ LINE Login) ไว้ในตาราง `users`
4. เปลี่ยนวิธีสร้าง notifier เป็น:
   ```python
   notifier = LineNotifier(channel_access_token="YOUR_TOKEN", dry_run=False)
   ```
5. ต้องติดตั้ง `requests` ก่อน: `pip install requests`

> หมายเหตุ: สภาพแวดล้อมที่ใช้พัฒนาต้นแบบนี้ไม่มีสิทธิ์เชื่อมต่ออินเทอร์เน็ตออกไปยัง
> เซิร์ฟเวอร์ LINE จึงทดสอบได้เฉพาะโหมด dry-run เท่านั้น แนะนำให้นำโค้ดนี้ไปทดสอบ
> โหมด live ต่อในเครื่อง/เซิร์ฟเวอร์ที่มีอินเทอร์เน็ตและ token จริง

## หน้าเว็บแดชบอร์ด (สำหรับเจ้าหน้าที่)

ไฟล์ `dashboard.py` เป็นเว็บแอปด้วย Flask ให้เจ้าหน้าที่เปิดดูรายการยืม-คืน
ทั้งหมด รายการเลยกำหนด ค่าปรับ และกดปุ่มเดียวเพื่อสั่งตรวจสอบ +
ส่งแจ้งเตือน LINE ได้จากหน้าเว็บโดยตรง (ไม่ต้องพิมพ์คำสั่งเอง)

วิธีรัน:
```bash
pip install flask
python dashboard.py
```
แล้วเปิดเบราว์เซอร์ไปที่ `http://127.0.0.1:5000`

ตอนนี้เปิดได้เฉพาะในเครื่องตัวเอง (localhost) เท่านั้น คนอื่นในคณะยังเข้าไม่ได้
ต้อง "deploy" ขึ้นเซิร์ฟเวอร์จริงก่อน (ดูหัวข้อถัดไป)

## การ Deploy ขึ้นใช้งานจริง (ให้คนอื่นเข้าถึงได้)

ตอนนี้ระบบเป็นแค่ prototype รันในเครื่องคนเดียว ถ้าจะให้เจ้าหน้าที่/นักศึกษาคนอื่น
เข้าใช้งานได้จริง ต้องทำเพิ่มตามลำดับนี้:

1. **หาที่ฝากรันเซิร์ฟเวอร์ (Hosting)**
   ต้องมีเครื่องที่เปิดทิ้งไว้ตลอด 24 ชม. ไม่ใช่คอมส่วนตัว ตัวเลือกที่นิยมและ
   เริ่มต้นง่าย (มักมีแพ็กเกจฟรี/ราคาถูกสำหรับโปรเจกต์นักศึกษา): PythonAnywhere,
   Render, Railway, หรือถ้าคณะมีเซิร์ฟเวอร์ของตัวเอง (on-premise) ก็ติดตั้งบนนั้นได้เลย

2. **เปลี่ยน Flask dev server เป็น production server**
   คำสั่ง `app.run(debug=True)` ใช้ได้แค่ตอนทดสอบ ของจริงต้องรันผ่าน WSGI server
   เช่น `gunicorn` (Linux) หรือ `waitress` (Windows) แล้วอาจมี `nginx` อยู่หน้าอีกที
   เพื่อความปลอดภัยและรองรับผู้ใช้พร้อมกันหลายคน

3. **เปลี่ยนฐานข้อมูลจำลองเป็นฐานข้อมูลจริง**
   ย้ายจาก SQLite ไฟล์เดียว ไปเป็น MySQL/PostgreSQL ที่รองรับหลายคนเข้าพร้อมกัน
   (ตามโจทย์คือให้เชื่อมกับระบบยืม-คืนที่คณะมีอยู่แล้ว ไม่ใช่สร้างฐานข้อมูลแยกใหม่ถาวร)

4. **ขอ LINE Channel Access Token จริง**
   สมัคร LINE Official Account + Messaging API ที่ LINE Developers Console
   แล้วเก็บ token ไว้เป็น environment variable (ห้าม hardcode ในโค้ด) เช่น
   ```bash
   export LINE_CHANNEL_TOKEN="xxxxxxx"
   ```
   แล้วในโค้ดอ่านค่าด้วย `os.environ.get("LINE_CHANNEL_TOKEN")`

5. **ตั้งโดเมนและ HTTPS**
   ถ้าต้องการรับ webhook จาก LINE (เช่น ให้ผู้ใช้พิมพ์คุยโต้ตอบกับบอทได้)
   LINE บังคับให้ endpoint เป็น HTTPS เท่านั้น ต้องมีโดเมนของคณะหรือใช้บริการ
   ฟรีอย่าง Let's Encrypt ออก SSL certificate ให้

6. **ตั้งเวลาให้ตรวจสอบอัตโนมัติทุกวัน**
   แทนที่จะให้เจ้าหน้าที่กดปุ่มเอง ควรตั้ง cron job (Linux) หรือ Task Scheduler
   (Windows) หรือใช้ library `APScheduler` ใน Python ให้รันฟังก์ชัน
   `check_and_update_fines` อัตโนมัติทุกเช้า

> สรุปสั้นๆ: ของตอนนี้พอสำหรับ "สาธิตแนวคิด" และทดสอบ logic ได้ครบ
> แต่ถ้าจะให้ใช้งานจริงในคณะ ต้องมีคนที่ดูแลเรื่อง server/hosting เข้ามาช่วย
> อย่างน้อย 1 คน หรือปรึกษาฝ่าย IT ของคณะว่ามีเซิร์ฟเวอร์ที่ใช้ฝากได้อยู่แล้วหรือไม่

## แนวทางต่อยอด

- เพิ่ม cron job หรือ scheduler (เช่น `APScheduler`) ให้รัน `check_and_update_fines`
  ทุกวันอัตโนมัติ แทนการรันมือ
- เปลี่ยนจาก LINE Notify (ซึ่งปิดบริการแล้ว) มาใช้ LINE Messaging API ตามที่ทำไว้ในโมดูลนี้
- เมื่อเชื่อมกับฐานข้อมูลจริงของคณะ ให้แก้ไขเฉพาะ `db_setup.get_connection()`
  ให้ชี้ไปที่ฐานข้อมูลจริง (เช่น MySQL) โดยโครงสร้าง query ใน `fine_calculator.py`
  ยังใช้ได้เกือบทั้งหมด (ปรับ syntax ให้ตรงกับ MySQL เท่านั้น)
